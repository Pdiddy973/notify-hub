# 2026-11-14

Phase 4 is finished: the Sonarr, Radarr and Prowlarr adapters are built in, from payloads captured on the real apps.

## Summary

- **Payloads:** captured on europa with a small Python listener on port 18090 instead of the dev hub on the PC, because the Servers VLAN cannot reach Trusted. Versions: Sonarr 4.0.20.3014, Radarr 6.4.4.10685, Prowlarr 2.7.0.5723.
- **Fixtures:** `server/test/fixtures/sonarr/`, `radarr/` and `prowlarr/`, one file per event. Scrubbed before saving: request tags (Seerr usernames) became `user1` to `user3`, indexer names became `Indexer A` to `D`, and download ids became fake GUIDs.
- **Adapters:** `server/src/adapters/builtin/sonarr.ts`, `radarr.ts` and `prowlarr.ts`, with shared helpers in `_arr.ts`.
- **Tests:** 229, all passing (215 before). Typecheck, lint, format check and the build are clean, and the compiled build loads all four built-in adapters with passing samples.

## Decisions

- **Every event is kept.** Adapters normalize every event the apps send, renames included, so the hub stores everything. Routing rules (drop or route) and event mutes then decide what is posted. Paul wants to collect a week of real traffic before choosing.
- **Event names:**

  | Event | Severity | When |
  | --- | --- | --- |
  | `grab` | info | A release was sent to the download client |
  | `import` | success | A file was imported |
  | `upgrade` | success | An import with `isUpgrade: true` |
  | `import-complete` | debug | Sonarr's second Download webhook per import, which has `episodeFiles` and no `isUpgrade` |
  | `rename` | debug | Files were renamed |
  | `movie-added` | info | Radarr added a movie |
  | `health` | warning | A health check failed; error when the app reports level error |
  | `health-restored` | success | A health check cleared |
  | `test` | debug | The app's Test button |
  | Anything else | info | Named after the app's eventType in lowercase with dashes, such as `series-delete` |

- **Keys:** grabs and imports carry `download:<downloadId>`, and health messages carry `health:<check type>`, ready for deduplication and state tracking later.
- **Links:** the apps send `applicationUrl` empty, so each Sonarr and Radarr source has an optional App URL setting (`appUrl`). Messages link to the series or movie page only when it is set. Health messages link to the Servarr wiki, and only https links are kept.
- **Images:** the poster's remote URL (TheTVDB or TMDB), https only.
- **Icons:** each app's 256 px logo from its GitHub repository.

## Still open

- **Upgrade:** no real upgrade payload was captured. The test reuses the import fixture with `isUpgrade` set to true; replace it with a real capture when one happens.
- **Prowlarr health** was not triggered. It goes through the same shared mapping as Sonarr's health events.
- **Seerr:** a test and an auto-approved payload were captured as well. They're kept outside the repository for a later Seerr adapter.
- **Per-source config UI:** `appUrl` can be stored through the API, but there is no form for it until the Phase 6 config forms.
- **Done-when check:** compare the stored messages from a week of real traffic on phoebe.

## Security review

Checked against the `CLAUDE.md` Security section.

- **Adapters:** they run in the existing isolated worker contexts and request no permissions, so they have no network access.
- **Links:** only https wiki links and http(s) app URLs are used. A test checks that a `javascript:` value is dropped.
- **Fixtures:** the repository is public, so usernames, indexer names and download ids were replaced before committing.
- **Unchanged:** no secrets, no log lines, no API routes and no migrations were added.

## Release and install

- **v0.1.0** released from `main` after PR #2 merged. The first tag was made on GitHub's release page as `V0.1.0`, which the Release workflow (`v*`) ignores. That release was deleted and `v0.1.0` was pushed with git.
- **install.sh bug:** `check_system` sourced `/etc/os-release` into the script's own shell. Debian's file sets `VERSION="13 (trixie)"`, which replaced the release tag, so the install failed with `release 13 (trixie) not found`. It now reads `ID` in a subshell. The phoebe install used a patched copy of the v0.1.0 script.
