## Phase 1: Core pipeline

- **Database:** all 11 tables from the plan, created by the first migration in `server/migrations/`. Migrations run when the hub starts, and the bot token and source tokens are stored encrypted.
- **Webhooks:** `POST /hook/<source>/<token>`, or the token in an `X-Hub-Token` header.
  - The token is checked before the request body is read.
  - A wrong token gets the same 404 as an unknown address and is logged in the discarded table with only a hint of the token.
  - Passwords and API keys in a payload are hidden before it's stored.
- **Message format:** color by severity, the source name at the top and the event type at the bottom. Text is cut to Discord's limits with an ellipsis.
- **Bot:**
  - Logs in, saves the server's text channels, and sends messages in order.
  - Messages wait in the queue while the bot is offline.
  - After a restart, unfinished work is picked up again.
- **Adapter errors:** if an adapter can't read a payload, an error embed is sent instead and the raw payload is kept.
- **Seed script:** `npm run seed` saves the bot token, server, one test source and one route. It's temporary until the Phase 2 setup page. It checks the bot token's format, and prints test commands for curl and PowerShell.
- **Tests:** 67, all passing.

## Problems solved

- **"An invalid token was provided":** the seed was first given the Application ID, then the Public Key. The bot token is on the Bot page, under Reset Token. The seed script now detects both mistakes.
- **curl sent nothing:** in the VS Code PowerShell terminal, `curl` is PowerShell's own web command, which doesn't accept curl's options. Use `Invoke-RestMethod`, or run curl from Command Prompt or Git Bash.

## Decisions

- **Release and install testing:** postponed until most features are built.
- **Migrations folder:** `server/migrations/` instead of `server/src/db/`, so releases include it without an extra build step.
- **Built-in `standard` adapter:** accepts JSON that is already in the hub's message format. The test source uses it.
- **Two extra columns on `messages`:** `normalized` and `error`, so the message detail page can show them.
- **Field limit:** an embed shows at most 25 fields, Discord's limit. The plan also mentions 10; this is still open.
- **Failed sends:** they aren't retried yet. Retries and rate-limit pacing come in Phase 6.
